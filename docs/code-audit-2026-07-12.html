Headline: one real chain worth fixing before this ships wide

The build is solid and the packaging bug from earlier is genuinely fixed. The one thing to prioritize is a security chain the terminal work opened up: the course terminal now trusts a client-supplied list of runnable binaries, and lesson markdown is rendered unsanitized — together they make “open a shared course → run arbitrary code” reachable. The server binds 127.0.0.1 only and is single-tenant, which caps remote exposure, but courses are explicitly meant to be shared and imported, so this vector is real. Two quick UI bugs and two one-line guard bypasses round out the priority list.

High

fix first

The two security items chain into remote-ish code execution; the two frontend items freeze the app’s only “fix a missing CLI” recovery path whenever the server hiccups.

Highsecuritythis sessionserver.ts:714 · command.ts:101–105

The course terminal trusts client-supplied extraBinaries — an arbitrary-binary exec primitive

checkCommandPolicy short-circuits to “allowed” for the whole command line whenever argv[0] is in policy.extraBinaries — and /course/command fills that list straight from the request body, with no server-side allowlist. The safety claim (“student-controlled, never lesson content”) is enforced only in the browser; the server has no independent basis for it. By contrast /course/task-check correctly never accepts extraBinaries — that route is the model to copy.

ReproPOST /course/command with {"line":"bash -c '…'","cli":"bash","allow":[],"extraBinaries":["bash"]} runs arbitrary code as the user. The tokenizer rejects a bare |, but bash -c '<script>' is one quoted token, so naming any shell/interpreter as argv[0] sails through.

FixDon’t trust extraBinaries from the request. Either drop it server-side and enforce the same cli/verb gate the task-check route uses, or persist the student’s opted-in binaries server-side and intersect the request against that set. At minimum, refuse shell/interpreter binaries (sh bash zsh python perl ruby node env xargs find) as extra binaries.

HighsecurityLessonRunnerView.tsx:896–900

Lesson markdown is rendered unsanitized — XSS that chains with the above into “import a course → RCE”

marked.parse() output is injected via dangerouslySetInnerHTML with no sanitizer. marked passes raw HTML through by default — <script> won’t run via innerHTML, but <img src=x onerror=…> and <svg onload=…> do. Lessons are written by Teacher tools to ~/.vpk/courses and are explicitly designed to be zipped, shared, and imported — so this is not strictly trusted repo content.

ChainImport a third-party course → a malicious onerror fires in the app origin → it fetch()s /course/command with extraBinaries:["bash"] (finding above) → code execution. This is the vector that turns the first finding from “local process only” into “open a shared course and get owned.”

FixSanitize marked output (e.g. DOMPurify) or configure a renderer that drops raw HTML. Worth doing even independent of the first finding — unsanitized lesson HTML has access to every /course/* and /settings route. (Pre-existing, but newly weaponized by the extraBinaries change.)

Highfrontendthis sessioncliProbe.ts:5–13

probeCli has no error handling — a server hiccup permanently freezes the CLI-fix UI

Unlike its sibling runProbeCommand, probeCli awaits fetch and res.json() with no guard, so a network blip or non-JSON 500 makes the promise reject. In CliPathFixer.check() that leaves status stuck on 'checking', so busy stays true and the input + Check button are disabled forever — freezing the only recovery path for a missing binary at exactly the moment the server is unreachable. Every rejection also hits the global unhandled-rejection handler, spamming the server error log.

FixWrap probeCli’s fetch/JSON in try/catch returning false (mirror runProbeCommand), or give each check() a catch that sets an error status. This primitive backs all four new tester components.

Highfrontendthis sessioncliProbe.ts:40

runProbeCommand parses JSON before checking res.ok

The fetch is wrapped, but await res.json() is not, and the !res.ok check happens after parsing. A non-JSON error response (a 500 HTML page, a proxy error during dev restart) throws in res.json(), rejecting probeVerb/probeStandalone → VerbTester/BinaryTester stuck on 'checking' plus unhandled-rejection noise. Same class as above.

FixParse inside try/catch, or check res.ok/content-type before .json().

Medium

worth doing soon

Two one-line guard bypasses in the command policy, a boot-safety gap in the new seed extraction, and three UI robustness issues in the new testers/terminal.

Medsecuritycommand.ts:117–120

“Deleting Nodes is never allowed” is bypassable via the no short alias

The guard matches node, nodes, node/…, nodes/… — but kubectl/oc also accept no as the built-in short name for Nodes. With delete in a step’s allow-list, kubectl delete no worker-1 (or no/worker-1, or fully-qualified node.v1.) evades the only thing standing between an allowed delete and destroying a Node.

FixNormalize the resource token and match the segment before .// against {node, nodes, no}.

Medsecuritycommand.ts:90, 121–123

The mutating --all-namespaces block is bypassable via =true

ALL_NAMESPACES_FLAGS is matched by exact token equality, but kubectl (pflag) also accepts --all-namespaces=true as a single token — so kubectl delete pods --all-namespaces=true slips past the cluster-wide-mutation guard.

FixMatch a === '-A' || a === '--all-namespaces' || a.startsWith('--all-namespaces=').

Medcorrectnessthis sessionseedCourses.ts:16–25 · content.ts:36

Seed-course extraction has no error handling and runs at module load — a bad asset kills server boot

extractSeedCourses() runs as a side effect when content.ts is imported, with no try/catch. If any single embedded asset is unreadable, the readFileSync throws an uncaught exception at import time and the packaged server fails to start entirely — instead of degrading to an empty catalog the way the snapshot-dir setup does elsewhere.

FixWrap the extraction body in try/catch, log via pushLog, and continue.

Medfrontendthis sessionVerbTester.tsx:53 · BinaryTester.tsx:46

Auto-probe-on-mount fires a burst of real process spawns when Settings opens

Every tester row runs check() on mount with no debounce or AbortController. Opening Settings › Education with N verbs + M binaries immediately fires up to 2N+M HTTP posts, each of which spawns a real CLI process server-side (<cli> <verb> --help). Ten verbs + five binaries ≈ 25 spawns the instant the tab renders; closing the modal mid-flight cancels nothing.

FixProbe lazily on the first “Test” click, or gate the auto-probe to the visible tab and stagger it.

Medfrontendthis sessionCliPathFixer.tsx:44

CliPathFixer’s success timer isn’t cleared on unmount

The setTimeout(() => onResolved(...), 700) before firing onResolved has no cleanup. If the component unmounts inside that window for a reason other than the resolve itself — closing the Settings modal, closing the terminal popout — the timer still fires onResolved, writing to localStorage (setBinaryPath) for a fix the user was abandoning.

FixHold the timer id in a ref and clearTimeout in a useEffect cleanup.

MedfrontendTerminalPane.tsx:192–218

The terminal double-submits on a fast double-Enter

The Run button is disabled={running}, but the Enter handler calls run() unconditionally and run() has no in-flight guard and never clears the input. Two quick Enters fire two concurrent /course/command posts of the same line and append two transcript + recall entries.

FixEarly-return in run() when running, or guard the Enter branch with !running.

Robustness and hygiene — real but low-likelihood or low-impact given the localhost, single-tenant model.

LowcorrectnessseedCourses.ts:17

First-run seeding guards on directory existence, not completeness

It returns early if ~/.vpk/courses exists, and the dir only comes into being mid-extraction — so a crash partway through (compounded by the no-try/catch item above) leaves it partial, and every later startup skips re-seeding. The student is stuck with an incomplete catalog and no self-heal. FixExtract to a temp dir and atomically rename on success, or check a “seeded” manifest instead of bare existence.

Lowcorrectnesscontent.ts · walkMarkdownFiles

A .md resource can masquerade as a lesson

Resources now live under <course>/resources/, and .md is an allowed upload type — but the lesson scan recurses into every subdirectory. A markdown resource with valid frontmatter would show up as a lesson in the catalog. Latent today (no .md resources shipped). FixSkip any resources/ path segment in walkMarkdownFiles/listLessonFiles.

Lowsecuritycommand.ts:167–203

runCourseCommand has no timeout and buffers output unbounded

Neither /course/command nor /course/task-check passes a timeout or size cap; stdout/stderr accumulate without limit. An allowed long-running or streaming command hangs the request and grows memory (a local DoS). probeBinary caps at 3s; the real runners don’t. FixAdd a wall-clock timeout + output-size cap and wire an AbortController from the route.

Lowsecuritythis sessionserver.ts:136–137

Startup PATH probe interpolates $SHELL into an execSync string

execSync(`${shell} -ilc '…'`) string-interpolates $SHELL into a command handed to /bin/sh -c. A $SHELL with metacharacters is startup command injection — practically it needs an attacker-controlled launch environment (already-compromised territory), and only runs in the compiled binary on non-Windows. FixexecFileSync(shell, ['-ilc','echo -n "$PATH"']) — no string interpolation. (Also note fish uses space-separated $PATH; the colon-split mis-parses but fails safe-ish.)

LowfrontendTerminalPane.tsx:163–171

Per-keystroke localStorage churn in the terminal

The whole session is JSON.stringify’d and written on every change of line (i.e. every keystroke), and the allow-lists re-read localStorage + parse ×2 and rebuild a Set on every render. Correct, just wasteful for a long session. FixDebounce the write (or key it off history/commandLog, not line) and memoize the allow-list reads.

LowfrontendVerbTester.tsx:39–51

Stale-outcome race in the testers

check() has no in-flight cancellation, so if testCli flips (via the CLI override) or the effect re-fires while a probe runs, the later-resolving probe wins and can paint a stale status. FixUse a per-run cancelled token — the pattern already used correctly in TerminalPane’s binary-probe effect.

LowfrontendBinaryTester.tsx:43

probeStandalone is fire-and-forget with no .catch

The best-effort --help run has no rejection handler, so a network/JSON failure produces unhandled-rejection noise (UI stays fine since status is already ok). FixAdd .catch(()=>{}) or set a benign outcome.

LowfrontendterminalAllowlist.ts:23–32

Allow-lists aren’t deduped → duplicate-key risk

readStringList doesn’t dedupe, and the UI keys list rows and the “Allowed” popover by the verb/binary string. The add handlers prevent dups, so it can’t happen through the UI — but a hand-edited or pre-existing storage value with duplicates would collide React keys. FixArray.from(new Set(...)) in readStringList.

Lowbuildbuild-course-assets.ts:53

Generated import specifier is single-quoted without escaping

The embed generator emits '../../../courses/${coursePath}' as a raw single-quoted string; a course filename containing ' or \ would emit syntactically broken TypeScript and fail the compile. Input is repo-controlled and current names are clean, so latent. FixJSON.stringify the specifier, or reject such names. (Same shape in build-web-assets.ts.)

coverage

Explicitly checked and found sound — so the report shows what was covered, not just what broke.

✓No shell anywhere in the exec path. All spawning uses spawn(cmd, argsArray) with no shell:true — classic metacharacter injection is structurally impossible at the exec layer.
✓Path-traversal guards hold. Resource and lesson path resolution reject .., separators, and absolute paths, and re-check with resolve + startsWith(dir+sep). The new <course>/resources/ layout preserves them.
✓The course embed → extract round-trip works end-to-end. The ../../../courses path is correct (the earlier ../../courses bug is genuinely fixed), the committed placeholder is empty, and a packaged binary will actually ship the four seed courses to ~/.vpk/courses.
✓The DMG build is self-healing. Resetting the generated placeholders before the typecheck gate means a prior interrupted build can’t break the next one.
✓/course/task-check is a genuine boundary — it never accepts extraBinaries and re-gates argv server-side. It’s the model the terminal route should follow.
✓The courseResourcesDir removal is clean — no dangling references anywhere; settings type, defaults, load/save, and tests all consistent (18/18 touched tests pass).
✓Nav gating is correct. Catalog/Course/Teacher render without a snapshot and are independently gated by their visibility toggles; the “none found in <dir>” message threads through both call sites.
✓The Help rewrite matches the code. 23 topics, no duplicate ids, all 16 view ids covered, all 5 figures present; Settings/Education, the Course terminal, and pop-out claims all spot-checked accurate.
✓The empty-catalog blank-terminal fallback and the popped-out width fix handle cancellation and state resets soundly; resolveLeadingCommand escapes regex correctly and the terminal transcript keys are stable.
Server binds 127.0.0.1 only, registers no CORS plugin, and the app is single-tenant/localhost — this materially caps remote exploitability of the security findings. The realistic path to the High-severity chain is importing a shared/third-party course, which the course model explicitly invites.

Suggested order

if you fix a few
  1. Stop trusting client extraBinaries in /course/command — the one change that closes the exec primitive; block shell/interpreter binaries at minimum.
  2. Sanitize lesson markdown — removes the app-origin XSS and breaks the import-a-course → RCE chain.
  3. Add error handling to cliProbe — two small try/catches un-freeze the CLI-fix UI and stop the error-log spam; highest bang-for-buck UI fix.
  4. Harden the two policy guards — the no alias and --all-namespaces=true are one-line matches each.
  5. Wrap seed extraction in try/catch — cheap insurance against a packaged-app boot failure.
